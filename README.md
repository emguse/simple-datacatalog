# Simple Data Catalog

手元のデータファイル（CSV / Parquet / JSON・JSONL）を登録して、次を管理する簡易データカタログです。

- アセット単位・カラム単位の **説明** と **タグ**
- アセット単位の **上流・下流（リネージ）** と、その **グラフ表示**
- アセット単位の **プロパティ**（オーナー・更新頻度などの標準項目＋カスタム項目）と **充実度**
- アセットの **ステータス**（運用中 / 非推奨 / 廃止）
- **ユーザー管理**（ログイン・ロールによる権限）と **変更履歴**
- **問い**：データが答えるべき問いを起点に、データの使われ方と必要な品質を管理

Python + Streamlit で動き、メタデータは SQLite（`data/catalog.db`）に保存します。

## 起動

```bash
uv sync
uv run streamlit run app.py
```

保存先を変える場合は、環境変数 `CATALOG_DB` に DB ファイルのパスを指定します。アップロードしたファイルは、DB と同じディレクトリの `uploads/` に保存されます。

**初回起動時**は「初期セットアップ」画面が出るので、最初の管理者アカウントを作成してください。

**スキーマの版が変わったとき**（アプリを更新したとき）は、起動時に自動で対応します。テーブルや列の追加だけで済む更新（v2 → v3：問いの追加、v3 → v4：ユーザーのメールアドレス・説明の追加、v4 → v5：アセットのステータスの追加、v5 → v6：指標とビジネスプロセスの追加）はデータを残したまま上げます。それ以外は、古い DB を `catalog.db.bak-日時` に退避して空の DB で作り直します（データは引き継ぎません）。
以降のユーザーは、管理者が「ユーザー管理」ページで追加します。追加したユーザーには仮パスワードが設定され、初回ログイン時に変更を求められます。

## ロールと権限

| 操作 | 閲覧者 | 編集者 | パワーユーザー | 管理者 |
|---|---|---|---|---|
| 一覧・検索・詳細・リネージ・アセットの変更履歴の閲覧、自分のパスワード変更 | ✔ | ✔ | ✔ | ✔ |
| 説明・タグ・プロパティ値・カラム・リネージの編集 | | ✔ | ✔ | ✔ |
| アセットの登録・データ更新（再取込・差し替え）・削除、ステータスの変更 | | | ✔ | ✔ |
| プロパティ定義の管理、ユーザー管理、全体の変更履歴 | | | | ✔ |

- ユーザーには **メールアドレス**（任意・重複不可）と **説明**（所属・担当など、任意）を登録できます。管理者は「ユーザー管理」で、本人は「アカウント」ページで編集します。
- ユーザーは削除せず **無効化** します（変更履歴に名前を残すため）。
- 有効な管理者が1人もいなくなる変更（最後の管理者の降格・無効化）はできません。
- パスワードは scrypt でハッシュ化して保存します。

## 複数人での同時編集

- 各フォームは **画面を開いた時点の値との差分（変えた項目だけ）** を保存します。別々の項目（例：Aさんがデータオーナー、Bさんが更新頻度）を同時に編集しても、両方の変更が残ります。
- 同じ項目を同時に変更した場合は、**後から保存した方が勝ちます**。上書きされた値は変更履歴で確認できます。
- 画面を開いた後に他のユーザーが内容を変えた場合は、「他のユーザーが内容を更新しました」と表示されます。「最新を読み込む」で最新の値に更新できます。
- 書き込みはすべてトランザクションの中で行います（SQLite の WAL モード）。リネージの循環チェックも同じトランザクション内で行うので、2人が同時に逆向きの関係を追加しても循環はできません。
- 想定しているのは、1台のサーバー（1つの Streamlit プロセス）を数人〜数十人で使う規模です。

## 使い方

1. **登録**：ファイルをアップロードするか、ローカルのファイル/ディレクトリのパスを指定します（例: `sample_data`）。カラム名と型は自動で取り込まれます。
   同じアセット名でもう一度登録すると **再取込** になり、名前が同じカラムの説明・タグはそのまま引き継がれます。なくなったカラムがある場合は、警告を確認してから削除されます。
2. **アセット詳細**：アセットの説明・タグ、カラムの説明・タグ（カンマ区切り）、直接の上流・下流を編集できます。先頭20行のプレビューも表示されます。
   循環するリネージは登録できません。
3. **リネージ**：中心アセットと深さ（1〜5）を選ぶと、上流・下流をグラフで表示します。
4. **ホーム**：キーワード（名前・説明・カラム名）とタグで検索できます。タグはカラムに付けたものでもヒットします。

## プロパティと充実度

アセットには、管理情報として **プロパティ** を付けられます。

**標準プロパティ**（🔒 削除・型変更はできません。名前・選択肢・必須・説明は変更できます）

| 名前 | 型 | 必須 |
| --- | --- | --- |
| ソースシステム | テキスト | ＊ |
| 更新頻度 / 公開範囲 / 機密区分 | 選択肢 | ＊ |
| 保持期間 | テキスト | ＊ |
| 利用上の注意 | 長文テキスト | |

オーナー・スチュワードはプロパティではなく、次の節の **役割割り当て** で管理します。

**カスタムプロパティ**：「プロパティ設定」ページで、名前・型（テキスト / 長文 / 数値 / 日付 / 選択肢 / URL）・必須を定義します。定義はすべてのアセットに共通です。

- **充実度**：アセットの説明、必須プロパティ、オーナー、スチュワードのうち、入力済みの数です（例：`充実度 7/10`）。オーナーは4つの責任範囲すべてに誰かが割り当てられていること、スチュワードは1人以上いることが条件です（ドメインからの継承を含む）。未入力でも保存はできますが、詳細ページとホームに未入力の項目が表示されます。
- **テキスト型**：これまでに入力した値が候補に出ます（表記ゆれを防ぐため）。
- **ホームでの絞り込み**：「未入力の必須項目があるものだけ」や、選択肢型プロパティの値で絞り込めます。キーワード検索はプロパティ値も対象です。

## アセットのステータス

アセットごとに、今使ってよいデータかどうかを **運用中 / 非推奨 / 廃止** で示します。登録時は運用中です。詳細ページで変更でき（パワーユーザー以上）、変更は履歴に残ります。データ更新や同名での再登録では変わりません。プロパティと違い、値は固定で変更できません。

- **ホーム**：既定で廃止したものを隠します（「ステータス」の絞り込みで表示できます）。廃止したものには充実度を出さず、「未入力の必須項目があるものだけ」の対象にもしません。
- **注意の表示**：詳細ページで、運用中でないデータを使っている有効な問いや下流のデータ、運用中でない上流のデータ（間接を含む）を知らせます。問いには 💡 ヒントとして出します。止めはしません。
- **候補と選択欄**：廃止したものは問いの「使えそうなデータ」に出しません。非推奨のものは候補には出しますが、最初から選んだ状態にはしません。アセットの選択欄やリネージのグラフには、運用中でないものだけステータスを添えます。

## 役割（データオーナー／データスチュワード）

`docs/question-driven.md` の設計に沿って、**オーナーとスチュワードの2層** で責任者を管理します。

| 役割 | 問いとの関係 | 持ち方 | 主な項目（＊は必須） |
|---|---|---|---|
| オーナー | 問いを引き受け、答えられることに責任を持つ | **役職** で持つ（異動に強い） | 組織＊、役職＊、担当者、責任の範囲＊（問いの受諾／定義／品質基準／アクセス承認）、委譲規程、最終確認日＊ |
| スチュワード（業務／技術） | 問いに答えられる状態を保つ | **人** で持つ | 組織＊、担当者＊、担当の範囲、問い合わせ窓口＊、エスカレーション先＊、最終確認日＊ |

- **ドメインと継承**：オーナー・スチュワードは「ドメイン」ページで、ドメイン単位に設定します（管理者）。アセットは所属ドメインの割り当てを継承し、例外だけをアセットの詳細ページで上書きします（パワーユーザー以上）。
  - オーナーは **責任の範囲ごと** に上書きされます。例：ドメイン「販売管理」のオーナーが営業部長（全範囲）で、アセット「売上実績」に経理部長（定義のみ）を設定すると、売上実績のオーナーは「経理部長＝定義」「営業部長＝問いの受諾・品質基準・アクセス承認（継承）」になります。
  - スチュワードは **種類（業務／技術）ごと** に上書きされます。
- **1行1割り当て**：役割の種類は `role_types` テーブルのデータです。3層化（例：データ管理責任者）は行を足すことで拡張できます。
- **棚卸し**：最終確認日から183日（半年）を過ぎた割り当ては「要確認（⚠）」になります。「役割の棚卸し」ページで、組織や役職・担当者で絞り込んで確認し、「確認済みにする」で最終確認日を更新します（人事異動の後などに使います）。
- 組織・役職・担当者などは自由入力です。過去の入力値が候補に出ます。

| 操作 | 必要なロール |
|---|---|
| ドメインの作成・編集・削除、ドメインへの割り当て | 管理者 |
| アセットのドメイン付け替え、アセットへの割り当て（個別設定） | パワーユーザー以上 |
| 閲覧（ドメイン・割り当て・棚卸し） | 全員 |

## 問い（データは問いに答えるために存在する）

`docs/question-driven.md` の考え方をもとに、「このデータでどんな問いに答えるのか」を自然に意識できるようにしています。
重い台帳を最初から埋めるのではなく、**一文から始めて、少しずつ育てる** 作りです。

- **一文から始める**：登録に必要なのは問いの文だけです（例：「得意先別の月次粗利はいくらか？」）。種別・必要な品質・受諾・監視担当・見直し日は、あとから書き足せます。
- **止めずに気づかせる**：足りない項目はエラーにせず、「💡 次に書くとよいこと」として表示します（疑問文になっていない、データが未特定、必要な品質が未記入、受諾済みなのに監視担当がいない、見直し日を過ぎた、など）。
- **候補を出す**：
  - 問いを書くと、似た問い（重複を避けるため）と、使えそうなデータを表示します。データの候補は、名前・説明・カラム・タグとの文字の重なりで探します。
  - 受諾者の候補は、紐づけたデータで「問いの受諾」を受け持つオーナー、監視担当の候補はスチュワードです。
  - 受諾にすると、受諾日が自動で入ります。見直し日は「半年後」をボタン1つで入れられます。
- **ふだんの動線に置く**：
  - **アセット詳細**：「このデータで答える問い」を表示します。0件なら「どんな問いに答えられますか？」と例を添えて促し、その場で1行で登録できます。リネージの下流を通じて支えている問いも表示します。
  - **ホーム**：キーワード検索で問いの文も探すので、知りたいことの言葉（「粗利」など）でデータが見つかります。カードには「❓ 答える問い N件」を表示します。0件のものは「問い未登録」とし、絞り込むと維持をやめる候補を洗い出せます（充実度とは別の扱い）。
  - **登録直後**に問いを書くよう案内し、**リネージ**のノードには問いの数を表示し、**棚卸し**には見直し日を過ぎた問いを出します。
- 問いの登録・編集は **編集者以上** が行えます。閲覧者は問いを見ることができます。

## 指標（ビジネスプロセスから導く数字の定義）

「どの業務（ビジネスプロセス）から生まれる、どんな数字か」を **指標** ページで管理します。問いと同じく、**名前だけで登録して少しずつ育てる** 作りです。

- 項目：名前（必須）、ビジネスプロセス、定義、計算式（文章）、単位、集計粒度。足りない項目は「💡 次に書くとよいこと」で示します。
- 元になるデータ（アセット）と、答える問いを紐づけます。アセット詳細に「このデータから算出される指標」が表示されます。
- カラム単位の計算式は、これまでどおりアセットやカラムの説明に書きます。
- ビジネスプロセス（受注・出荷など）は指標ページで管理します（パワーユーザー以上）。オーナーを継承する単位の「ドメイン」とは別のものです。
- 指標の登録・編集は **編集者以上**、閲覧は全員です。

## データを更新するとき

アセットを **削除して登録し直す必要はありません**。削除すると、入力した説明・タグ・リネージも消えてしまいます。
アセット詳細ページの **「データ更新」** から次のどちらかを選んでください。

- **元ファイルから再取込**：登録時のパスにあるファイルをもう一度読み込みます（ローカルパスで登録したファイルを更新した場合）。
- **ファイルを差し替え**：新しいファイルをアップロードして置き換えます。形式が変わっても構いません（CSV → Parquet など）。

更新後も残るもの：

| 対象 | 引き継ぎ |
| --- | --- |
| アセットの説明・タグ・リネージ | そのまま残る |
| 同じ名前のカラムの説明・タグ | そのまま残る（型は新しいファイルに合わせて更新） |
| 名前が変わったカラム | 画面で「対応する新カラム」を選ぶと引き継ぐ（`cust_id` → `CustId` のように大小文字や `_` だけが違う場合は自動で候補に入る） |
| なくなったカラム | 確認のうえ削除（説明・タグも消える） |

登録ページで既存アセットと同じ名前を指定した場合も、同じルールで更新になります。

## サンプルデータ

`sample_data/` には、`raw_orders.csv → orders_clean.parquet → daily_sales.jsonl` という流れを想定したデモ用データが入っています。

## 構成

```
app.py              ルーター（ログイン・ロールに応じたページの出し分け）
pages/              ホーム / 問い / 指標 / 登録 / アセット詳細 / リネージ / ドメイン / 役割の棚卸し / プロパティ設定 / ユーザー管理 / 変更履歴 / アカウント
catalog/db.py       SQLite スキーマ・接続
catalog/tx.py       書き込みトランザクション（BEGIN IMMEDIATE）
catalog/auth.py     ユーザー・認証・権限
catalog/changelog.py  変更履歴
catalog/properties.py  プロパティ定義・値・充実度
catalog/roles.py    ドメイン・役割割り当て（オーナー／スチュワード）・継承の計算
catalog/questions.py  問い（問い台帳）・ヒント・候補の提示
catalog/metrics.py  指標・ヒント・紐づけ
catalog/business_processes.py  ビジネスプロセス
catalog/ingest.py   形式判定・スキーマ推定・プレビュー
catalog/repository.py  アセット・カラム・タグ・リネージの CRUD
catalog/lineage.py  リネージのたどり・循環チェック・DOT 生成
tests/              pytest
```
